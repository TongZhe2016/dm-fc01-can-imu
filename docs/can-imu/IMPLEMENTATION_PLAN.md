# DM-FC01 CAN IMU 组成与实现

本文件描述交付实现；实机结果见 [VALIDATION.md](VALIDATION.md)，使用和构建入口见 [README](../../README.md)。

## 硬件与平台

MCU 为 STM32H743VIH6。保留厂商 PX4/NuttX 板级支持，基线提交 `b3d0fad488ac158d7af8cafb5de2b4ef8bc162b3`。专用目标 `damiao_dm-fc01_imu` 不启动飞行控制、姿态估计、MAVLink、UAVCAN 协议栈或 PWM 输出。

硬件事实核对自厂商《DM-FCO1 飞控板使用说明书 V1.1（2026-08-28）》、开发手册、引脚表和 CubeMX 工程，并与本仓库板级源码比较。

| 部件 | 接线 | 用途 |
|---|---|---|
| BMI088 加速度计 | SPI1，CS PA2，DRDY PA0 | 主流加速度 |
| BMI088 陀螺仪 | SPI1，CS PA3，DRDY PA1 | 主流角速度 |
| ICM45686 | SPI4，CS PC13，DRDY PE4 | 独立诊断源 |
| CAN1 | RX PD0，TX PD1 | 经典 1 Mbps 共线数据与对时 |
| USB | PA11/PA12，VBUS PA15 | NSH 维护、刷写、诊断 |
| 加热器 | BMI088 PD14，ICM45686 PD15 | 可选温控，默认关闭 |

CAN1 为唯一 CAN 接口，4-pin SH1.0 的 1/2/3/4 脚分别为 GND/VBAT/CAN_H/CAN_L；第 2 脚是电池电压。引脚表中 ICM 的另一组 PA4/PE2 项与 PDF/板级代码不一致，当前实现采用 PC13/PE4，已读取到实际传感器。

厂商启动脚本使用 `-R 4`（YAW180），部分说明文字称 PITCH180；当前保留经实机读取的固定驱动旋转。对照实物逐轴确认后才能固定 IMU→动捕外参；不根据安装竖直方向做水平矫正。

## 板上应用

`ROMFS/can_imu/init.d/rcS` 先启动 USB，加载参数，设置高速 FIFO，启动两颗 IMU；`CI_AUTOSTART=1` 时启动 CAN 模块。首次配置默认 0，完成 ID 与线路核对后开启并保存。

`src/modules/can_imu/CanImu.cpp` 独立消费加速度/陀螺 FIFO，传感器类型由 device_id 识别，不依赖枚举顺序。uORB 队列深度 16，并统计更新丢失。

数据处理：原始整数乘驱动 scale → 减逐轴偏置/温度斜率补偿 → 逐轴比例 → 两级一阶低通 → 公共 5 ms 时间网格的窗口积分平均。输出加速度比力（m/s²）、角速度（rad/s），保留重力响应。无世界坐标旋转或姿态估计。

每级低通默认 60 Hz，组合 −3 dB 频率约 38.6 Hz，低频群延迟约 5.3 ms；5 ms 窗口另有 2.5 ms 中心延迟。时间戳标记窗口末端，使用方必须保留这一语义。

缺口超过三倍原始周期时不插值跨越；不完整窗口丢弃。倒序样本忽略并计数。裁剪、轮询/未知时间戳明确标志，不能被滤波隐藏。

## 时间与双 IMU

64 位时间戳来自 MCU 启动后的单调微秒时钟，不需要电池、UTC 或电脑给 MCU 设置日历时间。每次流模块启动前递增并保存 boot/session，主机按 session 切换时间映射。

BMI088 使用真实 DRDY 时间戳时标为有效；回退轮询时置质量位。ICM 当前驱动轮询 FIFO，未恢复严格的逐样本硬件时间关系，因此只作为诊断源。当前不实施双 IMU 融合；先解决 ICM 计时、两颗 IMU 的轴系/偏置/杆臂和噪声，再考虑组合。

电脑以 10 Hz 请求对时，使用四个软件打点拟合 MCU→主机单调时钟，之后转换为 ROS 时钟。过期或 ROS 时钟跳变会使映射失效。拟合残差不等于绝对同步精度，具体打点位置见协议文档。

## CAN 传输

复用 H7 FDCAN 驱动，修复过滤器地址/初始化等待，显式启动驱动计时时钟，提供关闭和诊断寄存器。设备端不需要 SocketCAN。

样本 48 字节，8 个 DLC8 标准帧；每片带序号，整包 CRC 覆盖 baseID、序号和负载。另有 1 Hz 状态和 10 Hz 对时。32 个发送槽，3 ms 帧截止时间，过期清理。标准 ID 分配见 [PROTOCOL.md](PROTOCOL.md)，与电机 ID 1–4、参数 ID 0x7FF 分离。

主机重组限 32 个未完成包、20 ms 超时，检查 CRC、会话、序号、时间递增和有限数值。共线电机接收端必须只把 ENCOS ID 范围的帧交给电机解析器；主项目已修复其他标准帧误报故障的问题。

## 主机与 ROS

`host/can_imu/` 包含协议库、接收/统计、USB 查询、应用刷写和标定工具；接收仅依赖 Python 标准库，USB 使用 pyserial。原厂参数备份辅助工具可选依赖 pymavlink，运行时 IMU 不需要它。

`ros2/fc_clamp_can_imu` 安装同一份协议实现，发布 `/ee_imu/raw`、`/ee_imu/data` 和诊断。正式数据默认要求时间同步、完整样本、未裁剪、真实采样时间及标定有效；温稳可额外要求。姿态协方差首项 −1，六轴协方差为未知，不伪造精度。

两个 USB 维护进程使用同一硬件互斥锁，时间同步进程有独立单实例锁。主项目的 ROS 工作区通过符号链接引用本仓库包。

## 标定与温控

每颗 IMU 独立保存加速度/陀螺三轴偏置、比例和相对 48°C 温度斜率，默认偏置/斜率为零、比例为一、标定标记无效。陀螺静置和加速度六面工具生成待检查的参数命令；没有物理姿态证据就不设置标定有效位。

可选加热器各自使用 PI、60% 最大占空比、200 ms 温度陈旧检测、60°C 过温与五分钟升温超时锁存。停止模块关闭两路加热器。当前温控代码尚未完成热测试，默认关闭；当前 CAN 验收不依赖温控。

## 验收边界

离线协议/积分测试、USB 刷写、传感器读取、静止共线观察和两轮有界电机对照已完成。长时间连续流、实际 ROS 数据接收及交付仓库整理的结果统一记录到 VALIDATION。六面标定、外参、动态延迟和 EKF 接入是后续现场工作。
